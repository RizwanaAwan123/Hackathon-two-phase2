### What Would Happen When Deployed

If Minikube were installed and running, executing the deployment script would:

1. **Verify Prerequisites**
   - Check for Docker, Minikube, Helm, kubectl
   - Start Minikube cluster if needed

2. **Build Docker Images**
   - Build frontend image: `todo-frontend:latest`
   - Build backend image: `todo-backend:latest`

3. **Deploy to Kubernetes**
   - Install backend Helm chart
   - Install frontend Helm chart
   - Wait for deployments to be ready

4. **Provide Access Information**
   - Show URLs for accessing the application
   - Verify all services are running

### Expected Kubernetes Resources

**Deployments:**
- `todo-backend-backend-chart` - Running backend API server
- `todo-frontend-frontend-chart` - Running frontend UI

**Services:**
- `todo-backend-backend-chart` - Internal service on port 8080
- `todo-frontend-frontend-chart` - Internal service on port 80

**Pods:**
- 1 backend pod with health checks
- 1 frontend pod with health checks

### How to Deploy (When Minikube is Available)

```bash
# Start Minikube
minikube start --cpus=2 --memory=4096

# Run the deployment script
chmod +x deploy.sh
./deploy.sh

# Or deploy manually:
eval $(minikube docker-env)
docker build -t todo-frontend:latest ./frontend
docker build -t todo-backend:latest ./backend
helm install todo-backend ./helm/backend-chart
helm install todo-frontend ./helm/frontend-chart
```

### Accessing the Application

Once deployed, you would access the application at:
- Frontend UI: `$(minikube service todo-frontend-frontend-chart --url)`
- Backend API: `$(minikube service todo-backend-backend-chart --url)/api/health`
